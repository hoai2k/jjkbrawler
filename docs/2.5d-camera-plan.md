# 2.5D Camera — implementation plan & status

A Smash-style perspective camera for the existing 2D game, enabled with
`?camera=3d` and off by default (no param = today's renderer, unchanged).
No new art, no sim changes: fighters stay their current sprites,
billboarded into a real 3D scene, and every platform, hitbox and blast
zone keeps its exact 2D behavior.

## Status

Steps 1–7 of the implementation order are **built and smoke-tested**;
step 8 (garnish cards) is open. Deviations from the original plan are
called out inline as **[built]** notes.

| 2. Static scene (mapping, platforms, background plane) | ✅ done |
| 3. Billboards (fighters, projectiles) | ✅ done |
| 4. Rig (framing/dolly/yaw/lookahead/shake/kick) | ✅ done |

| 6. Drama hooks (intro, ult, domain, GAME) | ✅ done |
| 7. Board personalities + cues | ✅ done — all 20 boards wired |
| 8. Garnish cards (Crosswalk traffic, Lantern silhouettes, leaves) | ⬜ open |

Verification so far: `tools/smoke_camera.mjs` (headless rig invariants,
all passing), `tools/smoke_render_backend.mjs` and `tools/smoke_stages.mjs`
(flat mode untouched), plus in-browser screenshots of 3d mode with debug
hitboxes landing on the billboards.

Known, deliberate gaps in 3d mode:

- **Glow halos** (canvas `shadowBlur` on fighters) have no cheap GL
  equivalent and are skipped on billboards; strike arcs, particles and
  auras still draw on the overlay and carry the energy read.
- **Missing-art placeholder** boxes draw only in flat mode; in 3d a
  failed sprite logs the existing console warning.
- **Projectile comet trails** stay on the overlay canvas (additive
  strokes); only the projectile body is a scene quad.

## 1. Mode selection

```js
// main.js init(): lazy import, double-guarded
if (params.get("camera") === "3d") { const mod = await import("./render3d/index.js"); ... }
```

- `flat` is the default and the fallback. If WebGL context creation fails,
  log a console warning and run flat — never a broken screen.
- The 3D module is lazy-imported only when the param is set, so the flat
  path pays zero bytes and zero startup cost. three.js is only fetched in
  3d mode; the default game keeps its no-build-step, no-dependency
  property.
- **[built]** The mode gate lives in `src/camera_mode.js` — a tiny,
  three.js-free module both sides import — rather than an export from
  main.js (which render.js could not import without a cycle). It also
  carries `cameraCue()`, the feature-detected hook stage gimmicks poke.
- Later a Settings toggle can write the param and reload; the param stays
  the source of truth so a URL fully describes what a player sees.

## 2. Architecture: two stacked canvases

```
<canvas id="glCanvas">    ← NEW, z-index below, WebGL (three.js, vendored ESM)
<canvas id="gameCanvas">  ← existing, alpha, on top
```

In `3d` mode the scene (backdrop, domain planes, platforms, fighters,
projectiles) renders on `glCanvas`, and `render.js` skips its own versions
of those — but keeps drawing everything else exactly as today on the
transparent top canvas: particles, strike arcs, popups, banners, domain
overlays, vignette, flash, debug hitboxes, fighter adornments (shield
bubbles, meters, status effects, revival platforms).

Files, all as planned:

| file | owns |
|---|---|
| `src/render3d/index.js` | scene setup, draw entry point, resize, mode fallback |
| `src/render3d/rig.js` | the camera rig (§4) + the overlay projection (§5) |
| `src/render3d/billboards.js` | fighter/projectile quads, texture cache |
| `src/render3d/stage_geo.js` | extruded platforms, background/tint/domain planes |
| `src/config_camera.js` | every dial, comment-per-dial |
| `src/camera_mode.js` | **[built]** the mode gate + cue seam (see §1) |

`three.module.js` (r160) is vendored under `vendor/` — official ESM
build, no bundler.

## 3. Coordinate mapping

Sim space stays authoritative; the scene is a linear image of it.

```
S = 1/100                            // 100 sim px = 1 world unit
worldX = (x - 640) * S               // stage center at origin
worldY = (568 - y) * S               // +Y up; 568 = typical main-platform top
z = 0                                // the gameplay plane
```

- **Fighters / projectiles**: textured quads on `z = 0`.
  **[built]** Parity with the flat renderer is *by construction*: the
  quad's matrix is composed by replaying `drawCharFrame`'s exact canvas
  transform chain (translate, squash about `com`, rotate about `com`,
  mirror, image rect) in sim coordinates, inside a group whose transform
  is the mapping above. `frameMeta` placement, `currentFrame` pose and
  `motion.js` transforms are the same data the flat path reads.
  Afterimage trails ride the same quad builder.
- **Platforms**: boxes extruded `depth = 1.4` world units (main) / `0.9`
  (side/top), extruded *away* from the camera so the face stays on the
  gameplay plane. **[built]** The face of each box is painted by
  `drawPlatformShape` itself into a canvas texture — pixel-identical to
  flat mode — with lit top faces and dark sides; ghost/crumble/accent
  states re-key the texture and hide the solid faces.
- **Background**: the stage painting on a plane at `z = -14`, over-filling
  the frustum at max dolly-out. Stage `tint` and the flat renderer's
  darkening wash are translucent planes at `z = -6`; the domain
  expansion's dim + art + grade live at `z = -5`, behind the platforms
  and in front of the backdrop — the flat renderer's exact layering.
  (The optional second blurred parallax copy is not yet built.)

## 4. The camera rig

A perspective camera on a dolly, replacing pan/zoom while **reusing
`camera.js`'s existing targeting math** — `updateCamera()` runs unmodified
in both modes; the rig is a consumer of `state.camera`, never a
replacement.

**Lens.** `fov = 30°` vertical, near 0.1, far 60.

**Framing.** From the sim's zoom: `D = (720/zoom) * S / (2 tan(fov/2))`
≈ 13.4 world units at zoom 1. Position `(camX, camY + heightBias, D)`,
`heightBias +0.4`, `pitch -2°`.

**Yaw.** `clamp(camX * 0.9°/unit, ±4°)`, smoothed. Fights near a ledge
show that ledge's platform side-face; center stage is nearly head-on.

**Lookahead.** LookAt leads average alive-fighter vx,
`clamp(avgVx * 0.06, ±0.5)` world units.

**Shake / kick.** `cam.shake` → positional noise, world-scaled;
`cam.kick` → FOV punch `30° → 27.5°` over 60 ms, back over 180 ms —
every existing `cam.kick` call site inherits it.

**Drama hooks** (existing sim state only; `introT`/`endT` are now
mirrored onto `state` by main.js for the rig to read):

- **Ult cast** (`action.kind === "ult"`): dolly to 0.8×D on the caster,
  ±2.5° dutch, ease back.
- **Domain cast**: same arrival, then a slow 8 s drift-out while the
  domain overlay owns the screen.
- **GAME** (`endT > 0`): dolly to 0.7×D on the winner, yaw easing to 0.
- **Round intro** (`introT > 0`): start at 1.25×D with +6° yaw, ease in
  as READY…/GO! plays.
- **Respawn**: no special move (normal framing already includes the
  revival platform).

All constants in `config_camera.js`.

## 5. The overlay projection

Everything still drawn on the 2D canvas positions itself in sim
coordinates. In 3d mode `render.js` replaces `applyCamera`'s transform
with the affine fitted to the projection of the gameplay plane
(`rig.overlayTransform()`), so particles, popups, strike arcs and hitbox
debug land on the fighters with zero per-effect changes.
`rig.worldToScreen(x, y)` is exported for anything DOM-positioned.

**[built]** One refinement over the plan: the projection of the tilted
plane is a homography, not an affine — pitch + heightBias give it a ~1%
per-100-px scale gradient. The fit is therefore **pinned at the mean
alive-fighter position** (tangent there, wide-secant slopes): sub-pixel
exactly where hitboxes, particles and popups must coincide with the
billboards, with the residual pushed to empty frame corners
(`smoke_camera.mjs` asserts the tolerances).

## 6. Draw flow in 3d mode

As planned (§6 of the original): `draw()` branches once at the top;
`draw3d()` renders the scene, then replays the overlay list with the
projected transform, then the screen-space draws, unchanged.

## 7. Per-board flavor

**(a) Personalities** (`BOARD_CAMERA` in config_camera.js):
Garden Steps `yawBias 2.5°` · Sunken Crossing `dampingMul 0.5` ·
Domain Core `heightBias 0.7, dampingMul 0.7` · Shibuya `fovNudge +1°,
lookahead ×1.5` · Bridge Duel `driftFollow 0.4` (40% of the platform's
drift blended into the tracked x).

**(b) Cues** (`CUES` in config_camera.js, poked from stage_fx.js via
`cameraCue(name, strength)` — a no-op in flat mode): hush, surge, frenzy,
fangSnap, bloom, punch, wallYaw, rattle, layout, fog, inhale, wind,
lightning. Every board's gimmick moment is wired:

| Board | Cue |
|---|---|
| Quiet Hall | `hush` on the silence seal — push-in, yaw → 0 |
| Flooded Gate | `surge` with the wave's direction |
| Shibuya Night | `frenzy` for the 8 s curtain |
| Curse Maw | `fangSnap` biased toward the camera's edge |
| Garden Steps | `bloom` drift toward the flower |
| Lantern Corridor | `punch` on lantern impact |
| Neon Split | `wallYaw` while the wall stands, `punch` on a crossing hit |
| Bone Sanctum | `rattle` synced to each platform's rattle |
| Bridge Duel | (continuous `driftFollow`, no cue) |
| Academy Hall | `layout` pull-back for the reshuffle |
| Mist Pier | `fog` dolly-in while visibility is low |
| Crosswalk Rush | `surge` with the traffic direction |
| Cursed Teeth | `punch` on fang impact, `inhale` with release kick |
| River Gate | `wind` roll, re-cued signed on every flip |
| School Wing | `punch` on the curse-blob pop |
| Empty City | `rattle` on crumble, soft `punch` on reform |
| Billboard Roof | `lightning` — the strongest shake in the game |
| Domain Core / Sunken Crossing / Training Bridge | personality dials only |

**Garnish cards** (leaves, lantern silhouettes, traffic streaks, rubble
at z ≠ 0 — the "traffic passes in front of the fight" showcase) are the
remaining open item; each is an independent polish commit on top of the
scene this built.

## 8. Testing & performance

- **Smoke**: `tools/smoke_camera.mjs` runs the real `updateCamera()` +
  rig headless against scripted fighter paths and asserts framing
  invariants — fighters inside the frame with margin, dolly inside
  clamps, yaw/roll/fov bounded, no NaNs across KO/respawn/ult/domain/
  GAME/cue storms, and the overlay affine within tolerance of the true
  projection. No browser, no WebGL.
- **Parity**: debug hitboxes (`Backquote`) over the billboards are the
  in-browser acceptance test; verified by screenshot.
- **Budget**: a dozen boxes, ~10 quads, a few planes, no lights
  (MeshBasicMaterial throughout) — trivially 60 fps on integrated GPUs.
  Billboard textures are uploaded per frame-image on first use and
  cached; they reuse the already-loaded sprite images.
- **Resize/DPR**: `render3d.resize()` mirrors `resizeCanvas()`
  (`setSize`, `setPixelRatio(min(dpr, 2))`), aspect fixed by the same
  CSS letterbox.

## 9. Out of scope (deliberately)

3D character models, toon shading, porting particles/FX into the scene,
menu/HUD changes, any sim change. The `?render=billboard` backend
(per-character 3D models, `billboards/`) is a separate seam and composes
with this camera: that backend changes *how a character becomes pixels*,
this mode changes *the stage and lens they exist in*.
